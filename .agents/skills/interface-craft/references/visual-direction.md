# Visual direction, composition, and content

Read when choosing an identity, restructuring composition, or starting the visual design again.

## Basis and source status

Method: interface-craft heuristics distilled from the approved specification, 2026-10-03. These are design decisions, not official layout rules or user-research findings.

Supporting sources consulted 2026-10-03: [Apple Branding](https://developer.apple.com/design/human-interface-guidelines/branding) through official indexed excerpts (full body required JavaScript), and [Material 3 theming](https://developer.android.com/develop/ui/compose/designsystems/material3) through retrieved official documentation. They support brand expression within accessible, platform-aware systems; they do not endorse a particular composition below. Consult the platform references for source limitations and conventions.

## Establish the brief

Capture only what affects decisions: audience, primary task and action, representative content, platform, product tone, constraints, existing identity, and expected deliverable. State what success looks like in the user's terms. Infer routine choices from context; ask about consequential uncertainty without repeating answered questions.

Separate functional evidence from visual inspiration. When continuity is requested, reuse approved tokens, assets, and component behavior. When a new visual identity is requested, retain functional contracts and ignore the old composition and discarded inspiration. Neither path authorizes deleting the old application.

## Choose a direction

Use an already chosen direction. If identity is open and alternatives help, present two or three meaningfully different directions. Explain each through composition, type, density, palette, imagery, content treatment, and interaction, tying the choices to the product's task. Resolve consequential identity decisions; continue routine work within the brief and existing authorization.

Avoid filling every request with the same centered hero, cards, gradient, glass effect, icons, or animation. These treatments are options with specific purposes, not prohibited styles. Familiar controls reduce relearning; distinctive hierarchy, typography, and content can establish originality.

## Organize information before decoration

Choose representations by use: tables for comparison across shared fields; lists for ordered scanning; cards for independently meaningful items; charts for a supported quantitative relationship. Select navigation by destinations and task sequence. Prioritize the next useful action and recovery path over decorative density.

Use representative content, realistic length, and local language. Identify synthetic examples where presented. Show only supported capabilities, statuses, and evidence. Never fabricate usage metrics, customer testimony, API outputs, conversational memory, or processing stages to make the interface appear richer. If data is unavailable, design an honest empty/error state or clearly labeled prototype example.

## Turn the direction into a small system

Define semantic roles for surface, text, accent, outline, feedback, and focus; typography roles; spacing relationships; radii/borders; and purposeful motion. Choose values for this identity and platform rather than inheriting a universal aesthetic. Add reusable components and variants for actual repetition and states, not a speculative full library. Introduce themes only when needed.

Exercise a representative screen or section with long text, empty content, loading, errors, and enlarged type before expanding the composition. Review at relevant sizes using [quality review](quality-review.md).

Example: for a small publisher with an approved cream-and-ink identity, emphasize readable book information and a clear catalog action, preserve the brand, and use the selected web stack. A statistics dashboard, app-style navigation shell, or a new brand exploration would require a reason in that brief.
